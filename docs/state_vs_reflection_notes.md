# State 自检 vs Reflection 自检（机制对照笔记）

> 日期：2026-08-16 · 项目：`E-commerce_agent_v1.0.2`
> 用途：面试/复盘前快速捡起两套自检机制的分工与关联。

---

## 一句话结论

> **State 守"记忆入口"（决定什么写进长期记忆，影响未来）；Reflection 守"回复出口"（决定这条回复能不能发，影响当下）。**
> 两者同源——都是拿"用户原话 + 工具真实 result"当锚做一次独立 LLM 判定——但防线位置不同、防的东西不同、成本不同。

---

## 一、触发位置与干什么

| | State 机制 | Reflection 机制 |
|---|---|---|
| 代码 | `memory/state.py` + `memory/state_prompt.py` | `workflow/reflection.py` + `llm/reflection_prompt.py` |
| 触发点 | 回复确定后 `_update_state`（agent.py `_update_state`） | 出草稿、回发前（agent.py `run` 门控） |
| 触发条件 | **每轮都跑** | 本轮调过工具 **且** 轮次未满（省 token） |
| 检查对象 | 更新后的**事实条目库**（`self.text`，每行一条用户事实/约束） | 即将发出的**草稿回复** |
| 判定依据 | 用户原话 + 工具 result（真实锚） | 用户原话 + 工具 result + 草稿 |
| 输出 | 下一版条目库（≤200 字） | `{action, issues, revised_reply}` |
| 产出去向 | 注入下轮 system（`state.to_text()` → agent.py） | 决定本轮回什么 / 是否回环补工具 |
| 失败兜底 | `_clip` 字符截断 | `accept`（用原草稿），坏 JSON 不打断 |

## 二、内部流程对照

**State（state_prompt.py，对"事实条目库"做增删改）：**
- `state.text` = 用户事实条目库，每行一条（如 `- 预算：≤5000元` / `- 排除：联想`）
- 输入 = 旧库 + 本轮事件（用户原话 / AI 回复）+ 工具调用（工具/参数/result）
- 任务 = 逐条处理：改口替换对应行（不残留旧值）、放弃删行、新需求增行、否定记排除条目
- result 能佐证的约束可写入，与对话矛盾以真实结果为准
- 输出 = 换行分隔的 `- 内容` 条目，≤200 字；装不下按重要性淘汰低优
- **不依赖模型思考（reasoning）**：判定依据是原话 + result，模型开不开思考模式都不影响

**Reflection（reflection_prompt.py，三维判定）：**
- 组装输入：用户原话 + 本轮工具调用及真实结果 + 草稿
- 另起一次 LLM 调用，`response_format=json_object`
- 逐条检查：完整性（覆盖用户每条诉求）/ 真实性（事实有工具结果支撑）/ 规范性（客服语气、1~5 句）
- 三态：`accept` 直接用；`revise` 用 `revised_reply`；`continue_tool` 把 issues 回灌、补调工具再答
- 坏 JSON / 异常 → 一律 `accept`，宁可平庸不崩溃

## 三、核心差异

| 维度 | State | Reflection |
|---|---|---|
| 防什么 | AI 理解错 → 污染长期记忆（坏画像影响**后续所有轮**） | 回复漏点/编造 → 误导用户**本轮** |
| 判定依据 | 用户原话（增删改依据）+ result（真实锚） | 用户原话 + result + 草稿 |
| 时效 | 影响未来（持久） | 只影响当前这一条 |
| 校验锚点 | result 佐证/反驳"该不该写进条目库" | result 佐证/反驳"草稿事实成不成立" |
| 失败成本 | 高（错一次脏很久）→ result 强锚 + 改口覆盖规则 | 低（就这条回复）→ 宽松兜底 |

## 四、为什么触发频率不同

- **State 每轮跑**：闲聊/纯问答也可能改口、排除、新增偏好（纯对话里提炼），漏了画像就不准
- **Reflection 只调过工具才跑**：没工具就没有真实锚点，自检无意义白花钱

## 五、同源洞察（面试可讲）

两者本质是 **groundedness（用真实数据做锚）** 在"写"与"发"两个边界上的应用：

```
用户原话 + 工具真实 result
   ├──(写之前)→ State：对照"原话 + result" 维护条目库    防止"理解错进记忆"
   └──(发之前)→ Reflection：对照"原话 + result" 审草稿    防止"编造/漏点发出去"
```

再补一层：评测断言（T8，规划中）用黄金答案做锚，在"上线/回归"边界防退化。三层同一个思想，构成完整自检体系。

## 六、面试话术（30 秒）

> "我做了两道自检，本质同源：都另起一次 LLM 调用，拿'用户原话 + 工具真实结果'当锚回去审模型生成。写长期记忆前，State 把对话提炼成一张用户事实条目库（预算、排除项等），逐条增删改、用 result 校准，防理解错进记忆；发回复前，Reflection 拿同一组真实结果审草稿，防编造漏点。一个守记忆入口、一个守回复出口，一个持久、一个即时，职责不重叠，评测再在出口外兜一层黄金答案。"
